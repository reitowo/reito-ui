# Listbox / Transfer 同排与留白

日期：2026-10-10。实际查看用户提供的 Transfer 深色裁图，以及当前浏览器总览的组合页面。用户指出短名称 / 说明被强制拆为两行、选中行内距过小；另发现左右侧列表使用 items-center，内容数量不等时两侧标题和搜索框上下错位。

## 共享修正

- Listbox 默认 descriptionLayout=inline：名称与短说明同排；相关间隔来自 content-gap（12/16px），说明为次级文字。
- 选项行的左右 padding 为 menu-item-padding-x（12/16px），上下为 cell-padding-y（6/10px）；普通单行高 32/40px。
- 分组文字与选项名称共用横向起点。非虚拟长说明自然换行保留文本；显式 stacked 继续支持详细双行。
- 虚拟列表沿用固定行高和截断布局，同排 / 双行的排版探针与实际行保持一致；避免新样式仍使用旧双行估计造成滚动位置错误。
- Transfer 的两侧顶部对齐，中间操作自行居中；移动、过滤、受控值、禁用项与键盘契约不改。
- Storybook Listbox / Transfer 参数调试提供 descriptionLayout，并新增 Listbox 的双行说明预设。

## 检查结果

首次 48 项测试中 43 通过、5 失败：四个富选项行高检查发现名称和小号说明做基线对齐会合成 21px 行盒，多出 1px；已将文本容器及虚拟估算探针改为同样的垂直居中，保持 20px 文字行。另一个失败来自 Storybook 自带 axe 检查与手动检查同时运行；测试只对明确的 axe busy 条件等待重试，真实违规仍直接失败。最终重跑 48 项全部通过，覆盖 Transfer / Listbox / Listbox virtual 的移动、选择、连续范围、搜索、受控值、禁用/只读/加载、原生表单、长内容、虚拟远端定位和四主题密度无障碍。追加四组合稳定性回归通过；参数实时切换发现虚拟器保留旧估算缓存，已在布局 / 密度对应的探针高度改变时清空行测量缓存。最终 13 项虚拟回归全部通过，实时 inline → stacked → inline 的行高为 32 → 52 → 32px，DOM 数量保持有界。当前 52 个唯一相关用例通过（48 项列表 / 转移 + 4 项状态稳定性），不把重复重跑计算为新的用例。完整构建和最终检查结果另列。截图 .logs/transfer-inline-{theme}-{density}.png。参考图的缩放比例未知，数值是本库定义的 CSS px，不称为上游实际尺寸。

当前用户浏览器 dark/compact 已实际查看：写入文件 / 修改工作区内容、运行终端 / 执行本地命令均在一行，两侧标题与搜索框齐顶。保留列表选项的轻量结构，没有追加 Card 分区或分隔线。

## 选项图标补充

TransferItem 原已继承 ListboxOption.icon。本次补齐共用 Demo 的文件、编辑、终端、浏览器和策略图标，在 Listbox 增加稳定图标列：同一 options 集合只要有任一图标，其他项保留 16px 空列，全无图标不占位。语义次级颜色与 space-2 间隔保持，装饰图标 aria-hidden。

Storybook 增加“图标 · 混合选项”和“图标 · 无图标”；参数调试增加 showIcons，仅控制示例数据，不新增 Transfer 公共 prop。测试验证图标随选项双向移动、混合选项的文字起点、全部关闭时移除图标列、四组合图标尺寸与行高，以及不离开 Story 的图标开关。

首轮 17 项中 11 通过、6 失败，实际原因是开发服务仍缓存旧 catalog 模块；通过比较本地服务返回的模块与磁盘源码确认，触发文件时间变更后模块更新。未绕过断言，也未将源码支持当成页面已显示。用户浏览器已实际复核五个图标显示，紧凑行高继续 32px。缓存更新后 16 项回归通过；图标开关测试发现 Storybook meta 的 items 被后置 args 展开覆盖，已调整展开顺序，开关专项重跑通过。17 个唯一相关用例现均通过。npm run build 全工作区通过，Storybook 最终修正后单独重建；最终 npm run check 与 git diff --check 均通过。用户浏览器实测五个图标均为 16px，选项行保持 32px。
