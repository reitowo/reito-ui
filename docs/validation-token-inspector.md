# Token inspector completeness and visual review

Date: 2026-10-11 (Asia/Shanghai).

Reference: the local overview's old Tokens popup, followed by the user's feedback that the variable list was incomplete and that the first expanded table was unattractive. The rejected table was inspected at 1303 × 1244 in dark/compact mode: its four-column rows exposed long source paths and bindings, pagination reached 23 pages, and the popup occupied about 1057px of height.

## Final interface

The shared theme menu now owns `查看设计变量`; Overview and the detailed Lab no longer have independent Tokens buttons. Home retains its contextual design-language link and all four Lab routes can open the same inspector.

The inspector uses a stable 640px working height, clamped to the viewport. The new `foundation.inspector-height` role supplies that dimension. A short header, search field, category navigation, variable list and selected-variable detail pane replace the table. The list shows readable names, compact previews and values; source paths and aliases appear in the selected detail pane. Current theme/density definitions are shown by default. `全部模式` reveals the remaining variants. Small windows use the category selector and a collapsible detail area. All scrollable reading regions are keyboard-focusable through the existing quiet scroll-focus style.

The final source contains 907 DTCG definitions across seven groups. This count includes mode variants and color recipes, rather than implying 907 independent CSS properties. The catalog is generated by the same resolver and CSS namespace mapper as token compilation. It preserves raw source values, paths, aliases, CSS expressions and scope. Color recipes have no invented independent CSS variable. The current component-specific coverage remains five groups and 19 aliases; other components share semantic roles.

Current-page values are read from the document's CSS scope and update on root style/theme/density changes. They do not claim to inspect arbitrary nested component-local overrides. Export returns the complete source JSON independently of the current filter. These boundaries are stated in the interface and metadata.

## Actual validation

- The initial relevant interaction run passed 19 checks, including all four theme/density combinations, filtering, selection, live CSS values, empty-state height, menu focus restoration, all four Lab routes, export, Home and density-menu behavior.

The scroller now uses the shared keyboard-focus class and tabindex, and the narrow layout/accessibility check passed on rerun.
